Stack Panic: I turned the call stack into a furnace

Answer fast or the stack overflows. It is a typing game about real LeetCode problems, and the whole design is one cruel feedback loop: getting it wrong makes the game harder forever.

I Ierofantis · 7 min read · side project
🔥

Most "learn to code" games are calm. You solve a puzzle, a checkmark appears, you feel fine. I wanted the opposite: a game where a wrong answer is not neutral feedback but an injury the game remembers. So I built Stack Panic, where crates of real problems fall into a furnace on an accelerating timer, and the metaphor is the one every engineer already fears: the call stack, overflowing.

The core loop

A crate falls. On it is a real solution with one line blanked out, plus three candidate lines. You pick the right one, and then, the part everyone underestimates, you type it yourself. Pasting is disabled on purpose. The point is the muscle memory, not the recognition.

  • Correct → the crate is smelted in a shower of sparks.
  • Wrong → the furnace stokes itself. Spawns get permanently faster.

That last rule is the whole game. Difficulty is not a curve the designer sets; it is a consequence of your own mistakes. Eight crates stacked up unsolved and it is STACK OVERFLOW, game over. The panic is real because the ratchet only turns one way.

Design rule I kept coming back to: punishment should change the world, not just the score. A lost point is forgettable. A furnace that now spawns faster for the rest of the run is not.

Forging the decoys

The trick to a typing game about code is the wrong answers. Random noise is too easy to reject, so the decoys are forged by mutating the real line: off-by-one on a range, a flipped comparison, a min/max swap, [0] quietly turned into [-1]. They are the bugs you actually write at 2 a.m., which is exactly why they are hard to spot under a falling-crate timer.

The problems themselves are harvested from three public LeetCode solution repos into a single leetlib.json: 993 problems in the library. A separate test harness runs the blank-and-decoy engine over all of them, so I know every crate is solvable and every decoy is plausible before it ever falls.

Rewarding the streak

If mistakes stoke the furnace, streaks have to cool it, or the game is just cruel. So combos multiply score up to a cap, and two of them are named after things every engineer wants at the worst moment:

  • A five-hit streak triggers GC PAUSE, and spawns freeze while you catch your breath.
  • A ten-hit streak triggers O(1), and the game auto-clears the cheapest crate for you.

The jokes are load-bearing. They make the tension legible: you always know whether you are winning by whether the furnace is speeding up or the powerups are landing.

Two modes, one ladder

Battle is the arcade above. But there is also a calmer Code Library: all 993 problems as untimed training, with search, difficulty filters, and a little XP for each first solve. Accounts climb a career ladder that will feel familiar, Intern → Junior → Mid → Senior → Staff → Principal, and guests can play the whole thing with progress kept in the browser.

The shape of it

Under the hood it is deliberately small: a Vite client for the game, a Node server for accounts and the leaderboard, MongoDB optional (without it, the game runs guest-only and never blocks you from playing). The interesting engineering is not the stack; it is the tuning of one number, how much each wrong answer accelerates the spawns, because that single knob is the difference between "fun panic" and "unplayable."
