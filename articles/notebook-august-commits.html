A. Networking inside containers

1. Keep a container reachable after a process inside it takes over the default route

Goal. A process in the container (a tunnel client, a mesh sidecar) redirects the default route through its own interface, and the container must still accept inbound connections on its original interface.

Method. Record the original interface address and gateway before the takeover; afterwards, add a source-based policy rule for that address into its own routing table, idempotently:

ETH0_IP=$(ip -4 addr show eth0 | awk '/inet /{sub("/.*","",$2); print $2}')
ETH0_GW=$(ip route | awk '/default via/{print $3; exit}')
# ... let the process take the default route ...
while ip rule del from "$ETH0_IP" table 100 2>/dev/null; do :; done
ip rule add from "$ETH0_IP" table 100
ip route replace default via "$ETH0_GW" dev eth0 table 100

Prefer awk to grep -P: busybox images fail the latter with a non-zero exit, and an empty variable yields a rule that matches nothing.

Rationale. Such processes install fwmark policy routing at a low priority number (for example not from all fwmark 0xca6c lookup 51820 at priority 9). A destination-based exception at a higher number is never consulted. A SYN arriving on the original interface gets its SYN-ACK routed into the tunnel and never returns; from outside this looks exactly like a firewall DROP, which makes the firewall the wrong first hypothesis.

Verify. Apply only the routing change, leave the firewall untouched, and probe from a peer. Reachability returning proves the diagnosis; change one thing per test.

Limits. Unnecessary if the process itself exempts the interface's subnet at a priority lower than its own catch-all. Equally applicable to processes that replace the default route outright.

2. Write start-up mutations that survive container restarts without accumulating

Goal. Firewall rules, policy rules, routes and resolver edits applied at container start must not pile up across restarts.

Method. Delete until absent before every insert. iptables -D removes one matching rule per call and fails when none remain; ip rule del behaves the same:

while iptables -D INPUT -p tcp --dport 8118 -j ACCEPT 2>/dev/null; do :; done
iptables -I INPUT -p tcp --dport 8118 -j ACCEPT
while ip rule del from "$ETH0_IP" table 100 2>/dev/null; do :; done
ip rule add from "$ETH0_IP" table 100

Rationale. Under restartPolicy: Always a container restart reuses the pod sandbox: the network namespace, the emptyDir volumes and /etc/resolv.conf all survive. iptables -I and ip rule add have no uniqueness constraint; each restart adds one more copy, and netfilter evaluates chains linearly per packet, so latency grows with the restart count until probes time out.

Verify. In an unprivileged test namespace, run the script five times: the unguarded version leaves five copies, the guarded one leaves one. On a live workload, compare rule counts on a long-lived instance before and after.

Limits. Covers everything in a pod-scoped namespace or volume. A pod recreation is a fresh namespace and does not need it.

3. Make every resolver path in a container follow the same DNS

Goal. Daemons that resolve names on their own must reach a working resolver even when a tunnel client's firewall restricts port 53, and a restarted container must not come up without a nameserver.

Method. Rewrite the daemon's resolver at runtime from whatever the system resolver file contains:

TUNNEL_DNS="$(awk '/^nameserver/{print $2; exit}' /etc/resolv.conf)"
sed -i "s/^nserver .*/nserver ${TUNNEL_DNS}/" /etc/proxy/proxy.cfg

In any pre-up hook that repairs an empty /etc/resolv.conf, inject the pod's own dnsConfig resolvers, never the cluster DNS service address.

Rationale. A daemon with a hardcoded nserver sends UDP 53 directly; a tunnel client's firewall typically rejects outbound 53 except to loopback, even with its fail-closed mode off, while libc's getaddrinfo goes through the resolver file to the client's own resolver on loopback. Same container, two resolver paths, one blocked. Separately, wg-quick runs resolvconf -d wg0 on shutdown and empties the file; kubelet writes it only at sandbox creation, so a restarted container inherits the empty one; and under dnsPolicy: None with a NetworkPolicy denying in-cluster DNS egress, the cluster DNS address is unreachable by design.

Verify. Reproduce in local Docker, then resolve by hostname through the daemon's own health endpoint. For the empty-file case, write the resolvers into a failing container by hand and confirm it starts on the next restart.

Limits. Only relevant for software that bypasses libc: proxies, custom DNS clients, runtimes with their own resolver.

4. Drive asynchronous daemons by polling state, not by trusting exit codes

Goal. A start-up sequence that controls a daemon through a CLI must fail loudly when the daemon does not reach the required state.

Method. Retry prerequisites until their state confirms (an enable step: up to 5 × 2 s, fatal if never confirmed). Follow every connect with a poll of the status output (15 × 1 s, status | grep -q Connected) and ignore the exit code. Change daemon settings only in the disconnected state, and read them back with the matching get rather than trusting the set.

Rationale. CLIs that talk to a daemon asynchronously return when the request is accepted. A connect that is a documented no-op unless a mode is enabled still exits 0; a setting toggled after connect can trigger a reconfigure that never converges.

Verify. Stop the daemon mid-sequence; the script must fail instead of proceeding green.

Limits. Synchronous CLIs that block until the state is reached do not need the poll; check which kind you have.

B. Control loops and orchestration

5. Add hysteresis to probes and a breaker with single-flight to expensive client-triggered actions

Goal. Health state must not flap under scheduling jitter, and an expensive recovery action must not be triggered concurrently by every caller who observes the failure.

Method. Flip only after 2 consecutive failures, reset on any success, log transitions rather than samples, keep UNKNOWN on a single failure. Set explicit probe timeouts (Kubernetes defaults to 1 s; 5 s is a sane floor when the probe shares an event loop with real work). Wrap the action:

cooldown = min(base * 2 ** (failures - 1), cap)      # e.g. 5 s -> 300 s
if target in in_flight or now < cooldown_until[target]:
    return None                                        # refuse; no await between check and add
in_flight.add(target)
# on failure: drop the binding and re-pick with exclude={target}; serve the old
# target rather than returning 503; at most one recovery attempt per request

Rationale. A single-shot probe cannot distinguish a dead target from a coroutine scheduled late. Any expensive action that clients can trigger concurrently is a self-inflicted denial of service without single-flight.

Verify. Unit tests: one failure does not flip a healthy target; success resets the counter; cooldown opens and backs off exponentially; a concurrent caller is refused; the re-pick excludes the failed target. Export health, consecutive failures and a transitions counter, and delete the series of targets that disappear: gauges do not expire on their own.

Limits. Hysteresis hides real flapping for one extra cycle. Do not raise the threshold to cover a contended loop; fix the loop.

6. Keep external and internal recovery off the same cadence, and run costly cleanup only on real termination

Goal. A container that heals itself must not be killed by the liveness probe at the moment its own recovery starts, and a cleanup that costs something (an external logout, a lease release) must not run on every restart.

Method. If the container self-heals after k failures at period p, set the liveness probe to fail no earlier than about 2kp (internal 3 × 30 s → failureThreshold: 8). Keep the client's state in a pod-scoped emptyDir at its state directory, seeded from a .default copy baked into the image when empty (a plain mount would shadow reference data the client needs), and gate login on a local status query. Run the costly cleanup only when the pod is going away:

pod_is_being_deleted() {
  [ -n "$(kubectl get pod "$POD_NAME" -o jsonpath='{.metadata.deletionTimestamp}')" ]
}

Rationale. Two recovery loops with identical thresholds reach them simultaneously and the external one wins. A preStop hook fires on a liveness-triggered kill inside a still-alive pod, so cleanup-on-exit runs on every restart and turns restart storms into storms against whatever the cleanup calls. A script running as PID 1 gets no default signal handling: trap 'exit 0' TERM is required for any EXIT trap to fire.

Verify. On a throwaway cluster, confirm deletionTimestamp is set on delete, eviction and Recreate rollouts and empty on a liveness kill. Trace pod events to see which loop fired first.

Limits. emptyDir survives container restarts, not pod recreation. A client with no internal loop can keep a tight probe.

7. Declare ownership and placement; build a deploy mutex on create-if-absent

Goal. Declarative deploys must not conflict with manual changes, replicas must spread by count, concurrent deploys must queue, and shared credentials must be allocated evenly.

Method.

  • Under Server-Side Apply, never kubectl scale a managed object; change the value in the chart and let the declarative owner apply it.
  • Spread by count, softly, so a cordoned node never strands pods Pending: 
    topologySpreadConstraints:
  - maxSkew: 1
    topologyKey: kubernetes.io/hostname
    whenUnsatisfiable: ScheduleAnyway
    labelSelector: { matchLabels: { component: your-component } }
  • Take a lock on the API server, scoped to the step that touches the shared resource, with a TTL and stale takeover, released in an if: always() step: 
    until kubectl create configmap "$LOCK" --from-literal=holder="$RUN" \
        --from-literal=acquired="$(date -u +%s)"; do
  AGE=$(( $(date -u +%s) - $(kubectl get cm "$LOCK" -o jsonpath='{.data.acquired}') ))
  [ "$AGE" -gt "$LOCK_TTL" ] && kubectl delete configmap "$LOCK"   # e.g. TTL 1800 s, max wait 1500 s
  sleep 15
done
  • Allocate shared credentials least-loaded first: sort by current holder count with ghost holders (pod gone) filtered out, iterate in that order, and keep atomicity in the compare-and-swap (kubectl replace with resourceVersion), not in the sort.
  • Pin the readiness strategy across tool major versions (helm --wait=legacy where the watcher can hang). Under strategy: Recreate, trigger builds per image so a one-component change does not restart every pod, and re-supply unchanged images' live tags via --set, because --reuse-values does not back-fill literal tags.

Rationale. SSA assigns a field manager to every mutation and refuses a conflicting owner until the field matches again. The default scheduler scores free resources, not pod counts, so freeing space on a crowded node puts replacements straight back. Create-if-absent on the API server is atomic. First-fit allocation fills the first slot forever. Some CI servers' concurrency: group cancels the second run instead of queuing it.

Verify. Reproduce the SSA conflict, match the value, watch it clear. Patch a spread constraint onto a running Deployment before committing it. Test the lock for atomic acquire, stale detection and release. Run the sort on synthetic registry data that includes ghosts.

Limits. The ConfigMap lock is right for a handful of writers; under real contention use a Lease object with renewal.

C. Data and storage

8. Bound incremental scans over a mutable key with a half-open interval

Goal. A delta job over an index on a field that writers update must terminate under continuous inflow.

Method. Close the interval at the run's start time and store that time as the next watermark:

run_start = now()
match = {"updated_at": {"$gte": watermark - timedelta(minutes=5), "$lt": run_start}}
# ... aggregate ...
save_watermark(run_start)

The overlap below the watermark covers documents whose timestamp was assigned slightly before they became visible.

Rationale. Aggregations are not snapshot-isolated. Writers bump the key on live documents and move them ahead of the cursor; an open-ended scan meets them again and chases the head of the index instead of reaching an end.

Verify. Run the job under live writes; wall time must be bounded by the interval's size, not by the inflow rate.

Limits. Unnecessary when the key is append-only (insertion id, immutable created_at). Required for anything writers update, including file modification times.

9. Rebuild with replace, delta with merge; store blobs apart from state; cap in the stored unit

Goal. Full rebuilds must be fast, state documents must stay small, and a size cap must not silently exclude a class of inputs.

Method. Write full builds with $out (atomic collection swap, old one queryable meanwhile, indexes created once afterwards); keep $merge for deltas. Store large payloads in their own collection keyed by the event that produced them: zlib.compress(raw, 6) as binary with byte counts, a TTL index as the retention policy, a guard under the document limit (12 MiB under a 16 MB cap), the state document keeping only a length. Store after the state transition and swallow store errors so the store can never block the pipeline. Express the cap in the unit you store (256 KiB compressed, with an 8 MB raw guard before compressing) and log skips at WARNING with a running skipped/total ratio. For "current state per entity", keep a second corpus keyed by entity, upserted on success, with its own TTL: bounded by entity count, each document the latest known-good input.

Rationale. $merge upserts one document at a time, an _id lookup plus every secondary index, millions of times on a rebuild. The server fetches whole documents before projecting, so a blob inside a state document taxes every non-covered query of it. A cap on raw UTF-8 excludes two-byte-per-character scripts above half the nominal size; a skip logged at INFO every hundredth time is invisible.

Verify. Compression round-trip and decoder parity offline; mean document size before and after; the skip ratio visible within the first hour of a run.

Limits. Do not mix an $out rebuild with concurrent deltas into the same collection.

10. Split line-delimited formats on one byte sequence; verify uploads by parsing

Goal. JSONL must survive text payloads containing Unicode line separators, and a file uploaded to a remote worker must be complete and current before it is processed.

Method. Use split("\n"), never str.splitlines(), for JSONL. Upload to a temporary name, then mv -f. On the remote side, loop (20 × 15 s works) running a full json.loads over every line and comparing the line count to the local file; abort on mismatch.

Rationale. splitlines() splits on every Unicode line boundary (U+2028, U+2029, U+0085, U+000C, …), which text payloads legally contain inside JSON strings. Network volumes can have lazy read consistency: stat() reports the final size while read() returns short data for minutes. A reused worker still holds the previous file under the same name.

Verify. Feed a record containing U+2028 through both splitters. Upload a large file, read it back immediately and over time, compare byte counts and parse results.

Limits. A format genuinely defined on Unicode line boundaries needs the other splitter; JSONL is not one.

11. Measure a cache before building it; aggregate where the data lives; version incremental caches

Goal. A refresh job over a large time window must run inside the database rather than in an application pod, and an incremental cache must never silently lack new fields.

Method. Measure first: batch size against reply cap (a 300-byte projected document at batch_size(5000) fills 1.5 MB per reply against a 16 MB cap; use 50,000 and let the cap bound it); whether a projection fetches something the writer already stores atomically elsewhere (drop it after measuring agreement); whether the cache shortens anything but an indexed point lookup (if not, it is a second copy of every payload). Then move the work server-side: one pass projects a few scalar fields from the fat collection into a slim window collection keyed by event id ($merge, whenMatched: replace, incremental by watermark as in technique 8); derive "latest per entity" with $group + $top {sortBy: {started_at: -1}} + $replaceWith $mergeObjects + $out, hash-group only, no sort stage; build every downstream view as an aggregate over the slim collections with allowDiskUse and $topN for capped lists. Guard server-side string functions against type errors:

"body_bytes": {"$strLenBytes": {"$cond": [
    {"$eq": [{"$type": "$data.body"}, "string"]}, "$data.body", ""]}}

Honour the watermark only when a stored schema integer matches the script's, else force a full rebuild. Materialise derived fields once in the first stage. Time every stage, keep them non-fatal, and drop an outlier stage rather than tuning the job around it. Audit the UI for components that are mounted but never rendered and still poll.

Rationale. A delta path only rewrites moved documents, so a new field never back-fills without a forced full run. Client-side aggregation pays transfer and memory for bodies it only measures. One non-string value aborts a $strLenBytes pipeline.

Verify. Throughput per change (documents per second at each batch size over your actual round trip); stage timings; failures collected and reported at exit.

Limits. Server-side aggregation moves load to the database; check disk spill under allowDiskUse before relying on it.

12. Gate setup checks on the production code path; size the pod before adding a heavyweight client

Goal. A configuration that passes its setup wizard must behave identically in production, and a heavyweight client (a full browser-class process) added to an API pod must not be OOM-killed on first use.

Method. Build the wizard as a state machine (Source → Access → Extraction → Save, canNext = step === 0 || passed[step], loading a saved config resets both) where every green check is produced by the functions production runs: the access step replays the exact strategy (lightweight client; heavyweight client to obtain credentials then lightweight replay; or heavyweight throughout), the extraction step replays the production transform on the cached response. Keep the probe classifier dumb:

blocked = status in (403, 429, 503) or (len(body) < 8000 and BLOCK_RX.search(body[:20_000]))
ok      = 200 <= status < 300 and len(body) > 4000 and not blocked

Raise pod limits before the first launch (2 CPU / 2 GiB for a client that adds 400 to 800 MiB) and pin the client, its driver and its fingerprint library together at one protocol revision. Generate any config-write allow-list from the consumer's own enums. Render a model's self-reported confidence as the weakest signal, marked "not verified"; let measured hit rates decide.

Rationale. A check that does not execute production's code proves nothing about production. An allow-list that drifts from its consumer silently rejects valid shapes. A heavyweight client is a resource-class change, not a dependency.

Verify. Frontend build plus backend import on every change; the probe rule against known blocked and known good responses.

Limits. The byte thresholds (8,000 / 4,000) suit document-sized responses; re-derive them for APIs.

D. One generative slot between deterministic gates

Techniques 13 to 19 apply when a language model is allowed to propose a replacement query expression (a path predicate over a tree-structured document) whenever an existing expression stops yielding a field. The governing rule: deterministic code before and after exactly one model call, each stage a subprocess behind a dispatcher, and a single writer (human approval) for live configuration. Nothing the model says reaches production until deterministic code has run it.

13. Triage by aggregation, cluster by structure, send a bounded window

Goal. Send the model only the documents a new expression could fix, one representative per template, pruned to the part that matters.

Method. Triage in one aggregation with an exclusive $switch, first rule wins, bodies never decoded: blocked if status ∈ {403, 429, 503, 520}; dead_url if ∈ {404, 410}; infra if status ≥ 500 and no body; fixable if the transform failed with a body and a 2xx or null status; else other. Assert the buckets sum to the total.

Cluster per expression: sample 30 failed documents; fingerprint each as a hard key {block_stub | has_structured_block | size_bucket} (size edges 2k / 20k / 100k / 500k characters) plus the vocabulary of its structural attribute tokens, the labels a template author attached to nodes. Greedy single pass: a document joins the first cluster in its hard-key bucket whose vocabulary has Jaccard similarity ≥ 0.85 with its own and widens the cluster's set to the union; otherwise it opens a cluster. Drop clusters under 5% share. Decide document kind (single entity, index, blocked, not found) by ordered rules, the decisive one being the label of the top-level container, then by counting repeated sibling blocks: index = blocks ≥ 10 ∨ (paginated ∧ blocks ≥ 4) ∨ values ≥ 5.

Prune each representative with a three-stage function and fixed bounds. Denoise: remove subtrees with no semantics for the task (presentation, comments, vector graphics, executable payloads) except payloads that serialise application state, which in client-rendered documents are the only copy of the value; cap 120k characters. Localise: keep a header window (title, first two structured blocks ≤ 4k each, ≤ 12 metadata entries, ≤ 8k total) and one target window: enumerate anchor candidates in a fixed priority order of attribute patterns (≤ 60 per pattern), keep those whose text or value attribute matches the field's value shape, reject any whose 8 nearest ancestors include a boilerplate region, grow upward until the window holds ≥ 1,200 characters and continue while the parent stays ≤ 25,000; primary window ≤ 30k, a sibling document's ≤ 18k; under 800 characters send the whole denoised document. Orient: supply the anchor's ancestor path (≤ 6 levels, label plus identifier or first two attribute tokens) as a separate line.

Rationale. Content varies within a template; label vocabulary does not, so structure clusters and content does not. An index document with many copies of the target attribute passes any single-match test; only counting catches it. The first value-shaped node in a document is usually boilerplate; anchoring by value shape with ancestor rejection avoids it. A path lets the model express a location structurally instead of guessing.

Verify. The triage invariant on every run; cluster counts per expression; the effect of each pruning rule measured on a frozen benchmark (technique 18).

Limits. Threshold and buckets suit markup-heavy documents; re-tune for terse formats with small label vocabularies.

14. Budget reasoning as its own resource and decode deterministically when benchmarking

Goal. A reasoning model must always leave room for its answer, and two identical benchmark runs must agree.

Method. Keep the total pool moderate and add a server-side hard stop on the thinking block:

extra_body = {"chat_template_kwargs": {"enable_thinking": True},
              "thinking_token_budget": 512}          # useful range 256–768
temperature = 0.0; seed = <fixed>; max_tokens = 2000
# server: --reasoning-parser ... --reasoning-config {"<think>","</think>"}
raw = choice.message.content or getattr(choice.message, "reasoning_content", "")

Record finish_reason, output tokens, elapsed time and retries per input. For a model without a reasoning block, switch the reasoning parser off or its whole answer lands in reasoning_content.

Rationale. max_tokens is one shared pool; a reasoning model given a large budget spends it all thinking and answers with none, returning empty with finish_reason = length. Sampling above zero makes the evaluation non-reproducible at the granularity you report.

Verify. Count empty answers at several thinking budgets; rerun the benchmark twice with the same seed and diff the answers slot by slot.

Limits. Determinism is per model build and server version; re-measure when either changes.

15. Put a mechanical evaluator in the loop, ask once, reward withdrawal

Goal. Turn a model that answers on every field into one that answers only where its proposal survives execution.

Method. Run every proposed expression locally with the consumer's query engine and return the first applicable fault from an ordered list: does not compile → matched nothing → matched N > 1 (state that the consumer takes the first match) → bound to a single instance (an identifier of three or more digits, a positional predicate) → coupled to an attribute that encodes state rather than structure → categorical field returned a unit-only or label-only string → numeric field's string has no digit. With a known-good document available, add: zero matches on it, or a value different from its reference (numeric within 0.01, categorical exact). On any fault, append the assistant turn plus one user message ending "null is a correct answer", ask exactly once, keep the revision only if it parses. If escalating to a larger model, give it the base answer as an assistant turn plus the faults, no thinking, no second round, and escalate only when the evaluator rejected the final answer or the first model withdrew.

Rationale. The model cannot execute what it proposes; the evaluator can, in milliseconds. The model's contribution is bounded by the window it sees, so a larger model on the same window repeats the same fault classes.

Verify. On a frozen benchmark, compare usable proposals, junk and declines with and without the round; expect junk to fall and declines to rise while usable proposals hold. Test an escalation model on the same windows before adopting it; expect it to break working fields as often as it fixes broken ones.

Limits. One round. A second round mostly yields variations on the same fault; spend the budget on the window instead.

16. Assign verdicts in a fixed order, check combinators with the consumer's semantics, report two trial numbers

Goal. Distinguish a value from a label, keep every competing candidate visible, and let two producers hold proposals for the same field.

Method. Replay every proposal through the production parser and assign one verdict in fixed order: invalid → no_value → wrong_kind → instance_specific → ambiguous → usable; cross-validate on the expression's other sampled inputs and demote zero cross-hits to instance_specific. Publish in two passes: verify everything, then merge per (expression, field), summing impact for identical candidates and ranking by verdict, then cross-hits, then share. Where the consumer supports chains, check the chain with its own semantics (first candidate in order whose text parses wins, not a union) and mark it usable only if it hits on every sampled input and every member is usable; do not chain fields where the same syntax means union. Key stored proposals by every dimension that can legitimately differ, (expression, field, source). Trial current against proposed on 50 failed inputs of the right kind and 50 known-good inputs; a hit is a non-empty right-kind value; report losses (current hit, proposed miss, failed set) and regressions (same, known-good set) separately, and derive unverifiable → regression → gain → loss → no_gain. Show a distribution of returned values so identical label strings are visible.

Rationale. Presence counts cannot tell a value from a label. An upsert keyed too coarsely keeps whichever run came last. Two measurements under one label hide the important half.

Verify. Construct a case with one small and several large candidates for one field and confirm the merged chain hits on every sampled input; confirm two producers' rows coexist after the key change.

Limits. 50 + 50 bounds the regression you can see; size the samples by technique 17.

17. Validate against inputs that still work, sized by the regression rate you must catch

Goal. Detect proposals that fix the failing template and break the working one.

Method. Add a success gate at publish time and inside the loop over a sample of known-good inputs that carry the reference value production extracted from that exact body:

got = evaluate(doc.body, final_expression, field).get("value")
if not got:                      lost += 1
elif abs(float(got) - float(doc.reference)) > 0.01: mismatch += 1
if (lost + mismatch) and verdict in ("usable", "ambiguous"):
    verdict = "regressive"       # store counts and up to 3 mismatch samples on the row

Size the sample from the escape probability: a proposal that breaks a fraction p of known-good inputs escapes a gate of n with probability (1−p)n; for p = 5%, n = 25 gives 0.28 and n = 50 gives 0.08. Before proposing, run the current expression over the sampled failed inputs and mark the proposal current_works when it yields on all of them. Treat a human rejection as a terminal state in the upsert filter: suppress an identical re-proposal, re-file a different one with the rejection history attached. Surface the null outcome: an expression whose failed inputs are all of the wrong kind produces one policy row, asked once (status $nin [approved, rejected]). Before adding a dependency to close a suspected gap (a second parser, say), measure the gap with a read-only script.

Rationale. A validation set drawn only from failures cannot show a regression: a proposal for a minority template that matches nothing on the majority layout, or one that picks a neighbouring node with a plausible but different value, is invisible there. An idempotent regeneration loop re-files anything its filter does not treat as terminal.

Verify. Synthetic inputs: minority-template and wrong-node proposals draw faults, correct ones stay silent, an empty corpus is silent. A decision table for rejections: same candidate suppressed, different candidate re-filed with history, approved untouched, pending refreshed.

Limits. Without reference values on the known-good inputs you can only measure "lost", not "wrong".

18. Benchmark by re-scoring frozen inputs; rank by cost per usable output

Goal. Make runs weeks apart comparable and choose between configurations by the number you would pay for.

Method. Write the ground rules down and enforce them in tooling: re-score rather than re-read (a report command recomputes every historical verdict with today's evaluator); same frozen input set, temperature 0, fixed seed; the production parser is the oracle; inputs of the wrong kind leave accuracy denominators; unparseable output counts under stability, not accuracy. Define metrics as formulas: precision = usable / proposed (declines excluded); yield = usable / (inputs × fields); decline and wrong-decline rate; hold-on-siblings = cross_hits / cross_inputs; gain and loss on failed inputs; regression on known-good inputs as a gate that must be zero; agreement with a reference (numeric within 0.01 at the gate, 0.005 in the master comparison); parser drift; latency as median and tail per input, output tokens, runaway rate (hit the cap unfinished), feedback-round frequency; determinism as identical answers on rerun; confidence calibration. Report per-source distributions, never a mean. Rank by cost per usable output, tie broken by precision. Version the evaluation set per cycle, store it rather than re-fetch, and include per scenario a stated trap, a negative input where null is correct, at least two layouts and one known-good input per source.

Rationale. A benchmark whose oracle moves measures the oracle. A mean over sources hides that one source carries the number.

Verify. Re-score an old run with the current evaluator and confirm the report reproduces; rerun with the same seed and confirm identical answers.

Limits. Frozen inputs age; refresh the set per cycle from new failure modes and keep old versions to compare against.

19. Port regular-expression flags by semantics, not syntax

Goal. Move legacy patterns from PHP preg_* to Python re without turning bounded captures into whole-document captures.

Method. Parse delimiter and flags; map s/i/m/x; honour PCRE U by rewriting the greediness of every quantifier outside escapes and character classes (+ ↔ +?, counted {m,n} likewise). Strip nested markup and collapse whitespace from the capture before numeric cleaning. Order the strategy after structured data and the primary expression, and give it the same preference flag as the primary one so a source configured only with patterns is not shipped empty.

Rationale. U inverts greediness globally and has no Python equivalent; @open(.+)close@Us becomes a greedy capture to the last closing delimiter.

Verify. Every pattern compiles; re-validate live and expect most former "invalid" results to become "ok", with a handful of genuine no-matches.

Limits. Possessive quantifiers and other PCRE-only constructs need their own translation; audit every branch written before the new strategy existed.

E. Sessions through a gateway

20. Substitute credential placeholders after every encoding step; enforce identifier invariants at write and read

Goal. Sessions that are meant to be independent must actually get distinct upstream identities, and minted identifiers must never break the URL they are embedded in.

Method. Recognise the placeholder raw and percent-encoded ({session} and %7Bsession%7D), case-insensitively, at every step it passes through, and resolve it per namespace (host#stream) so every piece of per-session state is keyed together. Use two patterns for identifiers, one to mint and one to validate:

_SLUG_UNSAFE  = re.compile(r"[^a-z0-9]+")   # minting: collapse to a slug
_TOKEN_UNSAFE = re.compile(r"[^a-z0-9-]")   # validation: re-mint stored tokens in place

Treat an access token as bound to source address and client fingerprint: drop the token store when the pinned fingerprint is missing or when two fingerprint dimensions contradict each other (declared client family versus transport-layer family). When merging token lists from incremental renewals, dedupe by name keeping the latest expires.

Rationale. A placeholder that is never substituted is not a no-op; the upstream treats the literal as one session id for everyone. A # in a credential URL is a fragment delimiter. A single pattern used for both minting and validation flags every minted token and re-mints per request, destroying stickiness. A fingerprint contradiction is a positive signal of automation, not a degraded request. Assignment-order merging keeps the older token, bound to an address that has since rotated away.

Verify. Echo the upstream address through the gateway with the literal placeholder and with a per-host token; they must differ. Unit-test every failure path of any session mode falling back to a fresh session.

Limits. Two-pattern minting requires that stored tokens can be re-minted in place on read.

21. Make rotation policy per upstream; remember that reassignment is bounded by pool size

Goal. React to a flagged upstream address with the cheapest action that actually yields a fresh identity.

Method. Offer three reactions and choose per upstream, with a comment recording why it was last changed: mint a new session; rotate (reconnect the bound tunnel: a genuinely new address on the same pod, slow, disturbs other sessions there); reassign (move to another already-connected pod in the same region: fast, token unchanged). Make every mode fall back to a fresh session on any failure path (no base URL, 404, non-200, unreachable, no live token). For upstreams that limit per address, run a pinned pool: admit an address in three steps (echo it un-pinned, rebuild the credential with the pin and echo again requiring the same address, fetch requiring the configured status and no challenge markers); keep leases in a sorted set scored by available_at; evict only on the configured flag statuses, never on resource-level errors such as 404; draw any rotate-every-N threshold once per cycle.

Rationale. Reassignment cycles among existing pods, so on a two-pod pool its reachable set has size two; freshness on a small pool needs reconnection. Re-rolling a random threshold per request makes the effective threshold the minimum of N draws.

Verify. Render every configuration and diff against the previous render so exactly the intended upstreams change; unit-test the fallbacks.

Limits. The pinned pool assumes the upstream keys its limits on address; where it keys on the token, the pool multiplies cost for nothing.

22. Count the identities isolation forces you to keep alive before splitting a stream

Goal. Decide whether splitting one queue into N isolated streams will help or hurt.

Method. Count what each stream must own: its own token store, access token, session token, fingerprint pool and breaker, hence its own acquisition per renewal cycle. Compare N acquisitions per cycle against the acquisition step's throughput when that step runs one process-wide. Check whether streams on one region actually receive distinct addresses. If the split is for failure isolation and independent sizing, say so and size accordingly; if it was for address diversity, verify it delivers any. Keep the stream count in the queue registry so setup derives shards from one source. When reverting, leave the configuration commented in place with the reason next to it.

Rationale. The binding constraint on isolation is the number of identities the acquisition path can sustain, not pod count. Streams on the same region still share one address's rate budget.

Verify. Render configs and diff against the previous render; check deployment names against registered shards one-for-one; measure distinct addresses per region.

Limits. If the acquisition step scales horizontally, the constraint moves; re-measure rather than reuse this rule.

If you keep one technique: a container restart reuses the network namespace, the sandbox's resolv.conf and every pod-scoped volume. Four of the twenty-three entries (duplicate firewall and routing rules, the emptied resolver file, cleanup-on-restart storms, ghost lease holders) are the same mistake, a start-up script written as if it runs once. Make every mutation at start idempotent, and every cleanup conditional on deletionTimestamp.

F. Geometry

23. Drive a rigged skeleton from joint positions by stretching bones, not by inverse kinematics

Goal. Pose a skinned character from per-frame joint positions so that every joint lands exactly on its data point.

Method. Per bone, top-down: inherit the parent's rotation change since rest; swing the rest direction onto the data segment with setFromUnitVectors; take roll from an explicit hint (hip line, shoulder line, bend plane), blended to the inherited roll when the hint's perpendicular component falls below 0.12 of unit length; re-length limb bones to the data segment each frame, reading the segment head from where the bone actually is; drop any cached transform for a bone the moment its rotation is solved. Push baked animations through the same solver instead of copying quaternion tracks between rigs.

Rationale. Rotation alone cannot correct bone length, so error accumulates down each chain. A world matrix cached when a bone's position is read, before its rotation is solved, leaves the child composing against a stale parent. Quaternion tracks do not transfer between rigs whose bone frames differ.

Verify. Headless, over every frame in your data and every rig: limb joint error 0.0, roll error 0 wherever the hint is strong, every clip poses a standing body. Details in the retargeting post.

Limits. Stretching is invisible at a few percent; if the model's proportions differ grossly from the data, use IK for the end effectors instead.

Open claims, stated so they can be wrong

  • A linter that flags iptables -I, ip rule add and echo >> /etc/resolv.conf without a preceding delete loop would catch four of these twenty-three techniques' failure modes at review time.
  • The half-open interval rule (8) applies to every "process since watermark" loop over a mutable field, including log tailers keyed on modification time. A counterexample would be a scan where writers only ever decrease the key.
  • With a deterministic evaluator in the loop, a model's repair rate is bounded by the window it is shown, not by its size (15). Falsified if a larger model on an unchanged window fixes the "matched several nodes" fault class.
  • The escape probability (1−p)n (17) is the right sizing rule for any publish gate, with n chosen so the escape probability is below the human review rate.
