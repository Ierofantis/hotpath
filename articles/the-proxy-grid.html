The proxy grid: your address is part of your identity

You can get the TLS fingerprint and the headers perfect and still get blocked, because the address the request arrives on is a layer of the identity too, and defenses bind their trust to it.

I Ierofantis · 7 min read · adapted from The Quiet Fetch
🌐

A defense that grants your connection some trust grants it to a specific pair: this identity, from this address. If the same identity then appears from a different address, or the same address suddenly carries a dozen identities in a minute, the safe interpretation is suspicion. A real user's identity and address move together and change slowly. Something that hops between addresses request by request describes an infrastructure, not a person.

The rule this forces: an identity and its address are bound. A trust token minted on address A is worthless presented from address B, even with an identical fingerprint. The address is not a commodity you swap freely; for the length of a session it is part of who you are.

Stickiness is the requirement

So a session must keep its address for as long as it is a coherent session. Every request that session makes leaves from the same exit, presenting a stable pair for the defense to trust. When the session ends, whether it exhausted its request budget or was compromised, the next session may take a different address, because a new visit changing its address is exactly what a new visit would do. The unit of address stability is the session, matching the unit of identity.

Where the addresses come from

At any scale you need many addresses, and the naive answers are both wrong. One address per machine ties your address count to your machine count and pays for an exit on every box whether it is busy or not. A commercial pool drawn fresh per request dissolves the binding on every request. The answer is a pool of exits run as its own service: a grid.

Workers point at one entry point and encode what they want, a region and a session, into the proxy credential. The gateway reads it, picks a healthy exit in that region, binds the session to it, and forwards. Every request bearing the same session id routes to the same exit, which is the stickiness the identity layer needs, provided by the grid rather than arranged by hand. A distinguished form of the credential says "rotate to a fresh address first," which is how a worker asks for a new address when its current one is spent.

Health and load, quietly

The gateway does more than route. It discovers the available exits, health-checks each one continuously, and knows how many sessions each is carrying, so it can hand out the least-loaded healthy exit rather than whichever answered first. That matters twice over: an exit carrying too many sessions is both a bottleneck and, to a target, an address suspiciously busy for a residential line. Spreading sessions serves speed and plausibility with the same choice.

The takeaway

Treat the exit address as the bottom layer of the identity, not as plumbing. Bind it to the session, hold it for the session's life, rotate it deliberately when the identity turns over, and supply it from a managed pool that keeps addresses healthy and evenly loaded. Get the fingerprint perfect and then let the address wander, and you have undone the fingerprint's work one hop at a time.
